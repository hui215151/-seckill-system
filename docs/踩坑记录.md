## 一、构建与代码

### 1. 文件名少了 `.java` 的 `a`，Maven 直接找不到类

**现象**

```
[ERROR] .../mq/SeckillOrderConsumer.java:[18,13] 找不到符号
  符号: 类 SeckillServiceImpl
```

**原因**

仓库里提交的文件叫 `SeckillServiceImpl.jav`（扩展名少一个 `a`），Maven 不会编译它，于是 Consumer 引用的类不存在。

**解决**

```bash
git mv src/main/java/com/seckill/service/impl/SeckillServiceImpl.jav \
       src/main/java/com/seckill/service/impl/SeckillServiceImpl.java
```

**备注**：这是仓库本身的 bug，建议给上游提 PR，否则每个 clone 的人都会踩。

### 2. Lombok 的 `log` 被循环变量遮蔽

**现象**

```
[ERROR] TransactionCheckJob.java:[52,20] 找不到符号
  符号: 方法 info(java.lang.String,java.lang.String,java.lang.Long)
  位置: 类型为 com.seckill.entity.TransactionLog 的变量 log
```

**原因**

类上有 `@Slf4j` 生成 `log`，方法里又写了 `for (TransactionLog log : failedList)`，循环内 `log` 指向实体，`log.info(...)` 自然找不到。

**解决**

循环变量改名：

```java
for (TransactionLog txLog : failedList) {
    ...
    log.info("库存回补成功：transactionId={}, goodsId={}", txLog.getTransactionId(), goodsId);
}
```

**经验**：`@Slf4j` 的类里别用 `log`、`logger` 当局部变量。

### 3. `updateById` 的 id 为 null，事务表状态永远不落库

**现象**

秒杀下单成功、订单也生成了，但 `transaction_log.status` 一直是 `0`；`TransactionCheckJob` 的对账逻辑因此永远不会触发。

**原因**

```java
TransactionLog logEntry = new TransactionLog();
logEntry.setTransactionId(transactionId); // 只设了业务号
logEntry.setStatus(1);
transactionLogMapper.updateById(logEntry);  // 主键 id 是 null，实际更新 0 行
```

MyBatis-Plus 的 `updateById` 按主键更新，实体没有 `id` 时不会报错，只是静默更新 0 行。

**解决**

按业务唯一键更新：

```java
transactionLogMapper.update(null, new UpdateWrapper<TransactionLog>()
        .eq("transaction_id", transactionId)
        .set("status", 1));
```

失败分支同样处理（`status = 2`），定时任务才能扫到失败事务回补库存。

### 4. 改了 `application.yml` 却不生效

**现象**

配置里密码已经改了，应用日志仍然 `Access denied ... (using password: YES)`。

**原因**

1. `application.yml` 打在 jar 里，不重新 `mvn package` 就不会进包；
2. 旧 JVM 还占着 8080，`start-all` 看到端口被占就没启新实例，旧进程用着启动时缓存的旧密码死循环重连。

**解决**

```bash
# 改完配置必须重新打包
mvn -DskipTests package
# 确认 8080 的占用者并杀掉，再启动
powershell -c "(Get-NetTCPConnection -State Listen -LocalPort 8080).OwningProcess"
```

**经验**：改 `src/main/resources/**` 下的任何文件，都要重新打包；重启前先确认端口占用者是不是旧进程。

## 二、MySQL

### 5. 服务 PID ≠ 监听 3306 的 PID，导致连错实例

**现象**

`Get-Service MySQL80` 显示 Running、`ProcessId = 5108`，但 3306 端口属于 PID 7944；用「以为的」密码怎么都连不上。

**原因**

Windows 服务管理器里的 PID 可能是父进程/包装进程，真正监听端口的是子进程；再加上机器上还跑着 Smartbi 的独立 MySQL（6688），很容易张冠李戴。

**解决**

以端口为准反查真正的进程，再对服务：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3306 | Select OwningProcess
Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select ExecutablePath,CommandLine
```

**经验**：排查数据库问题时，先确认「你连的到底是哪个实例」，别只看服务名。

---

### 6. `--initialize-insecure` 只建了 `root@localhost`，从 127.0.0.1 连被拒

**现象**

```
ERROR 1130 (HY000): Host '127.0.0.1' is not allowed to connect to this MySQL server
```

**原因**

便携版初始化只创建 `root@localhost`；`my.ini` 里又开了 `skip_name_resolve=ON`，MySQL 不做反向解析，`127.0.0.1` 不会映射成 `localhost`，账号匹配不上。

**解决**

任选其一：

- 去掉 `skip_name_resolve`，让 `127.0.0.1` 反解为 `localhost`；
- 或在初始化时用 `--init-file` 补建账号：

```sql
CREATE USER IF NOT EXISTS 'root'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '<你的密码>';
GRANT ALL PRIVILEGES ON *.* TO 'root'@'127.0.0.1' WITH GRANT OPTION;
FLUSH PRIVILEGES;
```

**经验**：`Host 'x' is not allowed` 是**账号 host 不匹配**，不是密码错；`Access denied ... (using password: YES)` 才是密码/权限问题。

### 7. YAML 把纯数字密码当八进制解析

**现象**

密码明明是对的（命令行能登录），Spring Boot 启动却一直：

```
java.sql.SQLException: Access denied for user 'root'@'localhost' (using password: YES)
```

**原因**

```yaml
password: 012345   # 不带引号 → SnakeYAML 按八进制整数解析 → 5349
```

纯数字、前导 0 的密码会被 YAML 当成数字，JDBC 拿到的不是原字符串。

**解决**

```yaml
password: "012345"   # 一律加引号
```

**经验**：**配置里的密码永远加引号**，不管看起来多像数字。

---

### 8. 机器上原有 MySQL 的密码未必是项目要用的那个

**现象**

命令行能登录的那个密码、空密码、以及项目配置里写过的密码，在 3306 的 `root@localhost` 上都被拒。

**原因**

3306 是之前装 MySQL Installer 时初始化的实例，root 密码与项目配置里记的不是一回事，两者互相独立。

**解决**

不要动原有实例（可能还有别的业务在用），另起一个项目专用实例：

```
端口 3307 / root / <你的密码> / 库 seckill
```

并在 `application.yml` 改 `url` 的端口和 `password`。

**经验**：本地开发优先「一个项目一个实例」，别跟既有环境抢 3306。

## 三、Redis

### 9. JSON 序列化器把 Lua 参数包上引号，`tonumber` 得到 nil

**现象**

秒杀接口 500：

```
ERR Lua redis lib command arguments must be strings or integers
script: ..., on @user_script:17
```

脚本第 17 行是 `redis.call('decrby', stockKey, deductCount)`。

**原因**

`RedisConfig` 用 `GenericJackson2JsonRedisSerializer` 做 value 序列化。Java 传参 `"1"` 被序列化成带引号的 `"1"`，Lua 里 `tonumber('"1"')` 得到 `nil`，`DECRBY` 收到 nil 就报这个错。

**解决**

Lua 脚本改用 `StringRedisTemplate` 执行（参数按纯字符串序列化）：

```java
@Autowired
private StringRedisTemplate stringRedisTemplate;

Long remainStock = stringRedisTemplate.execute(
        stockDeductScript,
        Collections.singletonList(stockKey),
        "1"
);
```

**经验**：**用 Lua 时，key/value 序列化器要和脚本参数类型对齐**；JSON 序列化器适合对象缓存，不适合当脚本参数通道。

### 10. 便携版 Redis 装了不等于在跑

**现象**

`D:\redis` 下有 `redis-server.exe`，但 `redis-cli ping` 没反应，项目连 6379 直接报连接失败。

**原因**

解压版没有注册服务、没加 PATH、也没启动；`mvn` 构建、应用启动都不会自动拉起它。

**解决**

```powershell
Start-Process "D:\redis\redis-server.exe" -ArgumentList "redis.conf" `
  -WorkingDirectory "D:\redis" -WindowStyle Hidden
D:\redis\redis-cli.exe ping   # PONG
```

**经验**：中间件用便携版时，配一个 `start-all` 脚本统一拉起，别指望 IDE 或 Maven 帮你启动。

## 四、RabbitMQ

### 11. `SimpleMessageConverter` 只认 String / byte[] / Serializable

**现象**

秒杀请求 500：

```
SimpleMessageConverter only supports String, byte[] and Serializable payloads,
received: com.seckill.service.impl.SeckillServiceImpl$SeckillMessage
```

**原因**

Spring AMQP 默认用 `SimpleMessageConverter`，`SeckillMessage` 既不是 String 也没实现 `Serializable`，发送前就被拒绝。

**解决**

在配置类里注册 JSON 转换器，Spring Boot 会自动应用到 `RabbitTemplate` 和监听容器：

```java
@Bean
public MessageConverter jacksonMessageConverter() {
    return new Jackson2JsonMessageConverter();
}
```

**备选**：让消息类 `implements Serializable`，但 Java 原生序列化对字段演进不友好，不推荐。

---

### 12. 管理台 15672 打不开：插件没启用 / 环境变量没设

**现象**

5672 能连，浏览器打不开 `http://localhost:15672`。

**原因**

`rabbitmq_management` 插件默认不启用；且用 zip 版时 `ERLANG_HOME`、`RABBITMQ_BASE` 没设，`rabbitmqctl` / `rabbitmq-plugins` 会找不到 Erlang 或把数据写到默认目录。

**解决**

```powershell
$env:ERLANG_HOME   = 'D:\erlang'
$env:RABBITMQ_BASE = 'D:\rabbitmq\data'
D:\rabbitmq\rabbitmq_server-3.13.7\sbin\rabbitmq-plugins.bat enable rabbitmq_management
# 启停 broker 后生效，登录 guest/guest（仅本机）
```

**经验**：zip 版 RabbitMQ 的环境变量要同时给「服务进程」和「命令行工具」，只设一半会出现「服务能起、ctl 用不了」。

## 五、工具链与脚本

### 13. Maven 装了但 `mvn` 找不到

**现象**

`mvn -v` → `mvn : 无法将“mvn”项识别为 cmdlet...`，但 `D:\software\Maven\apache-maven-3.9.16\bin\mvn.cmd` 能跑。

**原因**

`MAVEN_HOME` 指到了父目录 `D:\software\Maven`，`PATH` 里是 `D:\software\Maven\bin`（不存在，真正的 bin 在版本号子目录下）。

**解决**

用户级修正（不需要管理员）：

```powershell
[Environment]::SetEnvironmentVariable('MAVEN_HOME','D:\software\Maven\apache-maven-3.9.16','User')
$p=[Environment]::GetEnvironmentVariable('Path','User')
[Environment]::SetEnvironmentVariable('Path', $p + ';D:\software\Maven\apache-maven-3.9.16\bin','User')
```

新开终端生效；已打开的终端 / IDE 要重启。

### 14. PowerShell 执行策略 Restricted，`.ps1` 静默失败

**现象**

双击或直接执行脚本没输出、没动作，退出码 1；`Get-ExecutionPolicy -List` 显示 `LocalMachine = Restricted`。

**解决**

用 `.bat` 包一层，显式绕过（不改系统策略）：

```bat
@echo off
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0start-all.ps1"
```

**经验**：给非开发同事的脚本，永远配一个 `.bat` 入口，别要求对方改执行策略。

### 15. curl 下载 GitHub 文件报 `CRYPT_E_NO_REVOCATION_CHECK`

**现象**

```
curl: (35) schannel: next InitializeSecurityContext failed:
CRYPT_E_NO_REVOCATION_CHECK (0x80092012)
```

**原因**

Windows schannel 做证书吊销检查时连不上 CRL/OCSP 服务，直接判失败。

**解决**

```bash
curl -L --ssl-no-revoke -o xxx.zip https://github.com/...
```

只跳过吊销查询，**不跳过证书校验**（不要用 `-k`）。

### 16. `mysqladmin shutdown` 卡住，端口还占着

**现象**

`stop-all` 执行完，3307 仍在监听，后续连接全部超时/失败；进程没退出但也不响应。

**原因**

InnoDB 关闭阶段偶发挂起（数据量大、磁盘慢、异常退出后恢复等），`mysqladmin` 一直等。

**解决**

停止脚本里加超时兜底：

```powershell
& "$mysqlBase\bin\mysqladmin.exe" -h127.0.0.1 -P3307 -uroot shutdown
for ($i = 0; $i -lt 15; $i++) {
    if (-not (Get-NetTCPConnection -State Listen -LocalPort 3307 -ErrorAction SilentlyContinue)) { break }
    Start-Sleep -Seconds 1
}
if (Get-NetTCPConnection -State Listen -LocalPort 3307 -ErrorAction SilentlyContinue) {
    Stop-Process -Id (Get-NetTCPConnection -State Listen -LocalPort 3307).OwningProcess -Force
}
```

**经验**：开发脚本可以「优雅优先、超时强杀」；生产环境不要这么干，要先看 error log。

---

### 17. `Start-Process` 的子进程继承了 stdout，管道一直不返回

**现象**

`powershell -File start-all.ps1 | Out-String` 一直挂起，但服务其实已经起来了。

**原因**

脚本里 `Start-Process` 拉起的 java / 批处理进程继承了父进程的 stdout 句柄，管道等待所有持有者关闭，于是永远等不到 EOF。

**解决**

- 用 `Start-Process ... -RedirectStandardOutput/-RedirectStandardError` 重定向到文件；
- 或直接 `Start-Process powershell -ArgumentList '-File', ...` 脱离当前管道，不要 `| Out-String`。

## 六、业务与文档

### 18. 防重 key 只有 5 秒 TTL，等于没防住

**现象**

同一 `userId` 连续秒杀，5 秒内第二次被拒（符合预期），但隔几秒再请求又能下一单。

**原因**

```java
redisTemplate.opsForValue().setIfAbsent(userKey, "1", 5, TimeUnit.SECONDS);
```

TTL 写死 5 秒，而业务目标是「同一用户同一商品只能秒杀一次」。

**建议**

TTL 至少覆盖整个活动周期，或改成「订单状态驱动」的幂等键（下单成功才释放/永久保留），不要用短 TTL 做业务防重。

---

### 19. 每次启动都用 DB 库存覆盖 Redis

**现象**

应用重启后，Redis 里 `seckill:stock:*` 被重置为数据库当前值，和重启前已预扣的数量对不上。

**原因**

`@PostConstruct initStockToRedis()` 无条件 `set(key, goods.getStockCount())`。

**建议**

只在 key 不存在时初始化（`setIfAbsent`），或从「DB 库存 - 已售数量」推导，避免重启把在途订单的预扣覆盖掉。

### 20. README 与代码不一致

| README 写的 | 代码实际 |
|---|---|
| `POST /api/seckill/goods` | `@GetMapping("/goods")` |
| JWT 鉴权 | 引入了 `jjwt` 依赖，但没有任何拦截器/过滤器，接口可直接调用 |

**建议**：以代码为准修 README；JWT 要么补实现，要么从技术栈里删掉。

### 21. 样例数据的秒杀时间已过期

`sql/seckill.sql` 里两条商品的 `start_time/end_time` 是 `2026-07-22 ~ 07-23`，当前代码不校验时间所以能跑；一旦补上时间校验，就会全部提示「活动未开始/已结束」。

**建议**：演示前把时间改成当前时间附近，或用相对时间（`NOW()`、`DATE_ADD`）。

## 附：给仓库维护者的建议

1. 修掉 `.jav` 文件名和 `log` 遮蔽，否则项目 clone 下来无法编译；
2. 给 `application.yml` 加一份 `application.example.yml`，密码用占位符，避免把真实凭据提交进仓库；
3. 补一个 `.gitignore`（至少包含 `target/`、`logs/`、`*.log`），本地环境说明类文件也不要提交；
4. 防重 TTL、库存预热、JWT 三处与 README 描述不一致，建议统一。
